Introducción

Este documento describe el diccionario de datos del esquema núcleo de PANYPAN. Está pensado para lectores no técnicos y explica qué información se guarda, por qué y cómo se conecta. Un diccionario de datos es como un “manual del sistema nervioso” de la base de datos: define cada tabla (entidad), las columnas (atributos), los tipos de datos, restricciones y las relaciones entre tablas.

Alcance

  • Cubre el esquema core del sistema: ubicación, parámetros, cadena de suministro y negocio.
  • No incluye procesos ETL, reportes externos ni módulos satélite.
  • Base de datos objetivo: MySQL 8.0+.

Cómo leer este manual

  1. Cada entidad corresponde a una tabla (p. ej. company).
  2. En la sección Columnas verás nombre, tipo de dato, si permite nulos, valor por defecto y descripción.
  3. En Restricciones se listan PK/UK, FK y reglas de borrado/actualización.
  4. En Relaciones se explica con palabras simples el “uno a muchos”, “muchos a uno” o jerarquías.
  5. Usa el filtro por Tag (debajo) para ver solo las entidades de un área (Ubicación, Parámetro, Supply chain, Core negocio).

Filtrar por Tag

Haz clic sobre uno o varios tags para activar el filtro. “Todos” limpia la selección.

Convenciones y buenas prácticas

  • Nombres en singular: product, category.
  • Claves foráneas con sufijo _id: p. ej. product.category_id.
  • id como PK entero autoincremental (BIGINT UNSIGNED).
  • Columnas created_at y updated_at con CURRENT_TIMESTAMP.
  • Restricciones explícitas (UNIQUE, FK) garantizan calidad de datos.
  • Reglas de borrado: RESTRICT (evitar borrar si hay uso), SET NULL (desasociar), CASCADE al actualizar IDs.

Glosario

Entidad (tabla)
Conjunto de datos del mismo tipo (p. ej., product).
Atributo (columna)
Característica almacenada dentro de una tabla.
PK (Primary Key)
Identificador único de cada fila.
FK (Foreign Key)
Columna que conecta dos tablas y garantiza integridad referencial.
UNIQUE
Restricción que impide valores repetidos en una o varias columnas.
RESTRICT / SET NULL / CASCADE
Comportamiento al borrar/actualizar datos referenciados.
Timestamp
Marca de tiempo de creación/actualización.

Preguntas frecuentes (FAQ)

¿Por qué `user` lleva backticks?

Porque user es palabra reservada en MySQL. Los backticks indican que es un identificador de tabla válido.

¿Puedo borrar una categoría padre con hijas?

El FK usa ON DELETE SET NULL: al borrar el padre, las hijas quedan sin padre (parent_category_id = NULL).

¿Por qué el consecutivo de factura es único por sede?

La restricción UNIQUE (headquarter_id, number) evita choques entre sedes y permite series independientes.

¿Se permite que una persona tenga varios usuarios?

El esquema no lo impide (no hay UNIQUE en user.person_id), pero a nivel de negocio suele preferirse 1:1.
